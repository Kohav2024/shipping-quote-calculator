# מחשבון הצעת מחיר לשילוח

אתר סטטי וציבורי להצעת מחיר ממחירון הספנות (ZIM, YML, OOCL, MSC). אין צורך בחשבון או בסיסמה — שולחים לאנשי המכירות את הקישור.

**כתובת חיה:** https://kohav2024.github.io/shipping-quote-calculator/

המחשבון בוחר אוטומטית את המחירון שחל ב**תאריך ההפלגה / BL**. מחירונים ישנים נשמרים לתמחור תיק כשהמכולה מגיעה. לכל חברה יש רשימה מקופלת ב«היסטוריית מחירונים» (החדש למעלה) — בלי גלילה ארוכה. אם כמה גרסאות חופפות באותו תאריך, נבחרת זו שהונפקה לאחרונה, עם מתג «גרסאות נוספות לתאריך זה».

## קבצים

- `index.html` — הממשק (עברית, מימין לשמאל, מותאם לנייד)
- `data/index.js` — מניפסט הגרסאות + מילונים משותפים (נמלים, קודי תוספות, תוויות, epoch)
- `data/notices.js` — הודעות לפי חברת ספנות (באנר, גיליון מלא, ואזהרה בהצעה)
- `data/spots.js` — מבצעי ספוט ממסוכנים (לא מחברת ספנות)
- `data/schedules.js` — לוחות הפלגות לפי חברת ספנות (מוצגים בתוך הצעת המחיר)
- `data/<חברה>/<תאריך>_….js` — קובץ אחד לכל גרסת מחירון (השורות עצמן). נטען רק כשצריך
- `.nojekyll` — כדי ש-GitHub Pages יגיש את הקבצים כמו שהם

## איך מוסיפים מחירון שבועי חדש

שולחים את קובץ המחירון החדש בשיחה כאן. העדכון הוא שתי פעולות קצרות (בלי לגעת במחירונים הישנים):

1. **קובץ גרסה חדש** תחת `data/<חברה>/`, למשל `data/zim/2026-12-01_v280.js`, בפורמט:

   ```js
   window.QUOTE_PACK = window.QUOTE_PACK || {};
   window.QUOTE_PACK["zim-v280"] = { rows: [ /* שורות packed */ ] };
   ```

2. **שורה אחת במניפסט** `data/index.js`, במערך `versions`:

   ```js
   {
     "id": "zim-v280",
     "carrierId": "zim",
     "file": "data/zim/2026-12-01_v280.js",
     "version": "280",
     "party": "ILHFA03-ZIM ISRAEL LTD.",
     "vf": 20,
     "vt": 50,
     "issued": "2026-11-25",
     "added": "2026-11-25",
     "sourceFile": "ZIM v280 (xlsx)",
     "label": "גרסה 280"
   }
   ```

   - `vf` / `vt` הם היסטים בימים מ-`epochUtc` (כרגע 11.11.2026). תאריך לפני ה-epoch הוא היסט שלילי.
   - `issued` הוא תאריך ההנפקה מהמחירון. אם לא צוין במסמך — נרשמים לפי תחילת התוקף ומסמנים `issuedApprox: true`, בלי להמציא תאריך.
   - `added` הוא התאריך שבו הגרסה נוספה למחשבון.
   - לא מעלים ל-GitHub מספרי הסכם, חוזה, הצעה (PQ), Trade ID, filing או מזהים דומים. לא שומרים אותם בתוויות, בהערות או בשמות קבצים.

אם בגרסה החדשה מופיעים נמל, קוד תוספת או הערה שעוד לא קיימים, מוסיפים אותם **בסוף** המערכים ב-`data/index.js` בלבד (append-only), כדי לא לשבור אינדקסים של מחירונים ישנים. לא ממציאים סכומים.

## איך מוסיפים הודעה לחברת ספנות

הודעות (הגבלות DG, שינוי שירות וכו׳) נשמרות ב־`data/notices.js` במערך `window.CARRIER_NOTICES`. לא נוגעים בקבצי המחירונים. לכל חברה אפשר להוסיף הודעה אחת או יותר — פשוט מוסיפים רשומה:

```js
{
  "id": "one-md1-dg-2026-11-18",
  "carrierIds": ["one"],
  "title": "כותרת ההודעה",
  "banner": "⚠️ הודעה חשובה: …",
  "publishedDate": "2026-11-18",
  "added": "2026-11-18",
  "effectiveFromVessel": "YM TRUST V.106W (MD12646W)",  // או ריק
  "validTo": null,           // או "2026-12-31" אם יש תאריך סיום
  "appliesWhen": "haz",      // "haz" = אזהרה בהצעה רק כשמסומן מטען מסוכן; "always" = תמיד
  "quoteWarningTitle": "⚠️ הודעה חשובה: …",
  "quoteWarning": "משפט קצר להצעת המחיר.",
  "sections": [
    { "kind": "meta", "text": "תאריך ההודעה: 18.11.2026" },
    { "kind": "p", "lead": "מה מתקבל:", "text": "…" }
  ]
}
```

- הבאנר הכתום מופיע מתחת לבחירת החברה רק אם תאריך ההפלגה / BL הוא ביום הפרסום או אחריו, וכל עוד לא עבר `validTo`.
- הודעה שהוחלפה נשארת בהיסטוריה: מגדירים לה `validTo` ליום שלפני ההודעה החדשה, והסטטוס בהיסטוריה הוא «פג תוקף».
- אפשר לצרף את הנוסח המקורי באנגלית בסקשן `{ "kind": "original", "lead": "נוסח מקורי", "text": "…" }` — מוצג במגירה מתקפלת.
- הודעות ישנות נשארות ב«היסטוריית מחירונים» של אותה חברה, עם תאריכים וסטטוס.
- `carrierIds` יכול לכלול כמה חברות אם אותה הודעה חלה על כולן.
- `appliesWhen` יכול להיות גם `"surcharge"`: אזהרה בהצעה רק כשכלל התוספת שעל ההודעה חל על ההצעה הנוכחית.
- אם יש תוספת שחלה לפי תאריך ומוצא/יעד (ולא לפי שורת מחירון), מוסיפים שדה `surcharge` לרשומת ההודעה: `perTeu`, `teuByType`, `effectiveFrom`, `match.ports`. הסכום נכנס לסה״כ בדולר בהצעה לכל גרסת מחירון של אותה חברה, בלי לשנות קבצי מחירון.

## איך מוסיפים מבצע ספוט ממסוכן

מבצעי ספוט (הצעות מנמל מוצא ליעדים, ממסוכן ולא מחברת הספנות) נשמרים ב־`data/spots.js` במערך `window.AGENT_SPOTS`. לא נוגעים בקבצי המחירונים או בהודעות. לכל מבצע מוסיפים רשומה:

```js
{
  "id": "msc-ningbo-20gp-2026-11-19",
  "carrierId": "msc",
  "carrierName": "MSC",
  "originKey": "NINGBO",
  "originHe": "נינגבו",
  "originEn": "Ningbo",
  "dests": ["ASHDOD", "HAIFA"],
  "destOnly": false,
  "source": "מסוכן",
  "agentName": "",            // אופציונלי; אם ריק מוצג «מסוכן»
  "received": "2026-11-19",
  "ft": 14,
  "tt": 25,
  "cutoff": "2026-11-23",     // או null — אז מוצג «לא צוין»
  "noMsdsBattery": true,
  "weightLimit": null,        // או { typ: "40HQ", maxTons: 18 }
  "ows": { "amount": 300, "ccy": "USD", "typ": "20DV", "minTons": 23 },
  "cancelFee": null,          // או { amount: 600, ccy: "USD", typ: "40HQ" }
  "sailings": [
    {
      "of": 4000,
      "ccy": "USD",
      "typ": "20GP",
      "etd": "2026-11-14",
      "etdDelayed": "2026-11-26",  // או null אם אין דחייה
      "availability": [
        { "dest": "ASHDOD", "typ": "20GP", "qty": 3 },
        { "dest": "HAIFA", "typ": "20GP", "qty": 1 }
      ]
    }
  ]
}
```

- המבצע מוצג בלשונית «מבצעי ספוט מסוכנים». אפשר לסנן לפי נמל מוצא או חברה.
- הצעה שפג תוקפה (עבר `cutoff`, או כל תאריכי ההפלגה בפועל — דחייה אם יש, אחרת ETD מקורי) מוסתרת כברירת מחדל. «הצג שפג תוקף» מציג אותה עם תגית.
- אם בחיפוש במחירון נבחר נמל שיש לו מבצע פעיל, מופיע באנר ירוק שמעביר ללשונית הספוט מסוננת לאותו נמל.
- לא ממציאים מחיר, זמינות, חתך או דמי ביטול. שדה חסר מוצג «לא צוין».

## איך מוסיפים לוח הפלגות

לוחות הפלגות נשמרים ב־`data/schedules.js` במערך `window.CARRIER_SCHEDULES`. לא נוגעים בקבצי המחירונים, בהודעות או במבצעי הספוט. מוסיפים רק לוח שהתקבל ממקור — בלי להמציא נמל, תאריך, או זמן הגעה לישראל.

```js
{
  "id": "yml-md1-suez-2026-11-19",
  "carrierIds": ["yml"],
  "service": "MD1",
  "received": "2026-11-19",
  "source": "See below vessels schedule via Suez Canal",
  "titleHe": "הפלגות קרובות (לוח MD1 מ־YML, התקבל 19.11.26)",
  "matchCodes": ["CNNGB", "CNSHA", "CNSHK", "SGSIN"],  // רק מוצאים שמופיעים בלוח ומתאימים לשמות במחירון
  "lastPort": "EGDAM",
  "ports": [
    { "code": "CNSHA", "key": "SHANGHAI", "name": "Shanghai", "col": "SHA" }
  ],
  "voyages": [
    {
      "newVoy": "MD12646W",
      "vessel": "YM TRUST",
      "comnVoy": "106W",
      "calls": { "CNSHA": { "etb": "2026-11-12", "etd": "2026-11-13" }, "EGDAM": { "etb": "2026-12-07", "etd": "2026-12-10" } },
      "starCalls": { "CNSHA": { "etb": "2026-11-22", "etd": "2026-11-23" }, "EGDAM": { "etb": "2026-12-15", "etd": "2026-12-18" } }
      // starCalls רק אם יש שורת * במקור; אם השורה ריקה — לא מוסיפים את השדה
    }
  ]
}
```

- בתוך הצעת מחיר של אותה חברה, אם שם המוצא שנבחר תואם ל־`key` של נמל בלוח (לפי שם המוצא במחירון, למשל `SHANGHAI` מתוך `SHANGHAI, CN`), מוצגות עד 3 הפלגות.
- הפלגה נכללת אם ה־ETD במוצא בשורה הראשית או בשורת `*` הוא ביום שנבחר או אחריו. המיון לפי ה־ETD המוקדם ביותר שעומד בתנאי הזה.
- לכל הפלגה מוצגים: האונייה, קוד ההפלגה, Comn. Voy, ETB/ETD במוצא, ו־ETB/ETD בנמל האחרון בלוח (`lastPort`). אם יש שורת `*`, היא מוצגת מתחת בדיוק כפי שבמקור, עם התווית `*`, בלי פרשנות.
- אין שידוך — אין בלוק. אין לחשב או להציג הגעה לישראל או לנמל שלא הופיע במקור.
- `key` חייב להתאים לשם המוצא במחירון. בלי כינוי שלא ניתן במקור (למשל Shekou אינה Hong Kong).
- שנות התאריכים נקבעות רק לפי כלל שצוין במקור (בלוח הזה: Nov/Dec = 2026, Jan/Feb = 2027).

מעלים לענף `main`, והאתר מתעדכן אחרי פרסום Pages.

אין שירות בתשלום ואין שרת נפרד: האתר רץ כ-GitHub Pages מענף `main`, מתיקיית השורש.
