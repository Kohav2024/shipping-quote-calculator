# מחשבון הצעת מחיר לשילוח

אתר סטטי וציבורי להצעת מחיר ממחירון הספנות (ZIM, YML, OOCL, MSC). אין צורך בחשבון או בסיסמה — שולחים לאנשי המכירות את הקישור.

**כתובת חיה:** https://kohav2024.github.io/shipping-quote-calculator/

המחשבון בוחר אוטומטית את המחירון שחל ב**תאריך ההפלגה / BL**. מחירונים ישנים נשמרים לתמחור תיק כשהמכולה מגיעה. לכל חברה יש רשימה מקופלת ב«היסטוריית מחירונים» (החדש למעלה) — בלי גלילה ארוכה. אם כמה גרסאות חופפות באותו תאריך, נבחרת זו שהונפקה לאחרונה, עם מתג «גרסאות נוספות לתאריך זה».

## קבצים

- `index.html` — הממשק (עברית, מימין לשמאל, מותאם לנייד)
- `data/index.js` — מניפסט הגרסאות + מילונים משותפים (נמלים, קודי תוספות, תוויות, epoch)
- `data/notices.js` — הודעות לפי חברת ספנות (באנר, גיליון מלא, ואזהרה בהצעה)
- `data/<חברה>/<תאריך>_….js` — קובץ אחד לכל גרסת מחירון (השורות עצמן). נטען רק כשצריך
- `.nojekyll` — כדי ש-GitHub Pages יגיש את הקבצים כמו שהם

## איך מוסיפים מחירון שבועי חדש

שולחים את קובץ המחירון החדש בשיחה כאן. העדכון הוא שתי פעולות קצרות (בלי לגעת במחירונים הישנים):

1. **קובץ גרסה חדש** תחת `data/<חברה>/`, למשל `data/zim/2026-12-01_v280.js`, בפורמט:

   ```js
   window.QUOTE_PACK = window.QUOTE_PACK || {};
   window.QUOTE_PACK["zim-v280"] = { rows: [ /* שורות packed */ ] };
   ```

2. **שורה אחת במניפסט** `data/index.js`, במערך `versions`:

   ```js
   {
     "id": "zim-v280",
     "carrierId": "zim",
     "file": "data/zim/2026-12-01_v280.js",
     "ref": "7110068521",
     "version": "280",
     "party": "ILHFA03-ZIM ISRAEL LTD.",
     "vf": 20,
     "vt": 50,
     "issued": "2026-11-25",
     "added": "2026-11-25",
     "sourceFile": "ZIM agreement 7110068521 v280 (xlsx)",
     "label": "הסכם 7110068521 · גרסה 280"
   }
   ```

   - `vf` / `vt` הם היסטים בימים מ-`epochUtc` (כרגע 11.11.2026). תאריך לפני ה-epoch הוא היסט שלילי.
   - `issued` הוא תאריך ההנפקה מהמחירון (Agreement Created On וכו'). אם לא צוין במסמך — נרשמים לפי תחילת התוקף ומסמנים `issuedApprox: true`, בלי להמציא תאריך.
   - `added` הוא התאריך שבו הגרסה נוספה למחשבון.

אם בגרסה החדשה מופיעים נמל, קוד תוספת או הערה שעוד לא קיימים, מוסיפים אותם **בסוף** המערכים ב-`data/index.js` בלבד (append-only), כדי לא לשבור אינדקסים של מחירונים ישנים. לא ממציאים סכומים.

## איך מוסיפים הודעה לחברת ספנות

הודעות (הגבלות DG, שינוי שירות וכו׳) נשמרות ב־`data/notices.js` במערך `window.CARRIER_NOTICES`. לא נוגעים בקבצי המחירונים. לכל חברה אפשר להוסיף הודעה אחת או יותר — פשוט מוסיפים רשומה:

```js
{
  "id": "one-md1-dg-2026-11-18",
  "carrierIds": ["one"],
  "title": "כותרת ההודעה",
  "banner": "⚠️ הודעה חשובה: …",
  "publishedDate": "2026-11-18",
  "added": "2026-11-18",
  "effectiveFromVessel": "YM TRUST V.106W (MD12646W)",  // או ריק
  "validTo": null,           // או "2026-12-31" אם יש תאריך סיום
  "appliesWhen": "haz",      // "haz" = אזהרה בהצעה רק כשמסומן מטען מסוכן; "always" = תמיד
  "quoteWarningTitle": "⚠️ הודעה חשובה: …",
  "quoteWarning": "משפט קצר להצעת המחיר.",
  "sections": [
    { "kind": "meta", "text": "תאריך ההודעה: 18.11.2026" },
    { "kind": "p", "lead": "מה מתקבל:", "text": "…" }
  ]
}
```

- הבאנר הכתום מופיע מתחת לבחירת החברה רק אם תאריך ההפלגה / BL הוא ביום הפרסום או אחריו, וכל עוד לא עבר `validTo`.
- הודעות ישנות נשארות ב«היסטוריית מחירונים» של אותה חברה, עם תאריכים וסטטוס.
- `carrierIds` יכול לכלול כמה חברות אם אותה הודעה חלה על כולן.

מעלים לענף `main`, והאתר מתעדכן אחרי פרסום Pages.

אין שירות בתשלום ואין שרת נפרד: האתר רץ כ-GitHub Pages מענף `main`, מתיקיית השורש.
